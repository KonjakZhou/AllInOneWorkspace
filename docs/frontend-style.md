# 前端风格约束与验证

## 规则放在哪里

- 把适用于整个仓库的要求写入 [AGENTS.md](../AGENTS.md) 的「Frontend visual consistency」。每条规则说明适用界面、应复用的组件以及验收条件。把接入例子和测试方法放在这份文档。
- 在 [全局样式](../src/styles.css) 维护颜色、边框、圆角、控件内边距和焦点样式。跨卡片、页面和弹窗复用的交互放在 `src/components/`。功能目录的样式负责该页面的布局和业务状态。
- 新增约束时先找项目中最接近的现有界面，再用共享组件或样式落实。可量化的要求用桌面用例断言。配色、密度和开合后的整体效果用实际 App 截图检查。修改已有规则时同时更新实现和对应测试。

## 单选下拉框的例子

卡片筛选、内嵌页筛选和账号表单统一使用 [ChoicePicker](../src/components/ChoicePicker.tsx)。触发按钮、右侧箭头和选项面板都由共享组件绘制。按钮内边距使用 `--control-icon-inset`，当前为 12 px。弹出层使用应用的表面色、边框和焦点样式，选中项显示勾选标记。空间不足时菜单向上展开，较长的选项列表在菜单内滚动。

普通表单传入 `showLabel` 显示字段名，紧凑筛选使用 `compact`。业务代码负责选项、当前值及必填条件，共享组件负责展示、定位和操作。调整箭头位置时修改共享样式，所有使用该组件的界面同步更新。

## 如何验收

- 用 Playwright 在 Electron 中打开控件，检查箭头离边缘的距离、弹出面板是否可见、选中项及确认后的值。卡片和弹窗各检查一次，账户列表等动态选项同时覆盖空态或禁用态。
- 用键盘验证方向键、Enter、Tab 和 Escape。关闭菜单后检查焦点去向。菜单位于弹窗内时，第一次 Escape 应关闭菜单，弹窗仍可操作。
- 在支持的最小窗口和卡片尺寸验证布局。涉及系统控件、焦点或弹出层的修改，用 `pnpm dist` 打包后再用实际 App 验证展开状态，而不是只检查关闭后的静态样式。
