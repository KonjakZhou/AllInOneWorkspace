# 架构与数据流

## 四层结构

```text
electron/                    桌面系统层
  main.ts                    窗口、菜单、原生文件对话框、受控 IPC
  preload.ts                 唯一暴露给界面的 DesktopAPI
  storage/                   串行存储、备份、原子写入
  feishu/                    本机 OAuth、凭证加密、账号连接、日历 API 与内存缓存
  telegraph/                 财联社签名请求、时间游标、历史缓存与限流
src/
  App.tsx + components/      工作区壳子、账号/组件库/设置界面
  workspace/controller.ts    自动保存、账号切换与工作区状态协调
  sdk/                       组件接口、校验、迁移、错误/加载/空状态
  widgets/*/widget.tsx       自动发现的具体组件
  shared/                    IPC 类型与持久化 Zod Schema
```

界面不使用 Node.js。主进程开启 `contextIsolation` 与 `sandbox`、关闭 `nodeIntegration`，校验 IPC 调用来源，拒绝新窗口、导航和默认权限请求。preload 仅暴露指定的账号与数据方法，不暴露通用 IPC、文件系统或系统命令。此设计参考 [Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security)。

账号是工作区身份，不是权限边界。同一设备上的操作系统用户可以访问全部本地数据。

## 数据模型

- `AccountIndex`：版本号、当前账号 UUID、账号名称和创建时间。
- `Workspace`：版本号、所属账号 UUID、组件实例数组 `widgets` 和保留记录数组 `savedWidgets`。
- `WidgetInstance`：实例 UUID、类型 ID、组件数据版本、配置、数据及网格坐标 `{ x, y, w, h }`。
- `SavedWidget`：记录 UUID、用户可命名的名称、保存时间及完整 `WidgetInstance` 快照。记录 ID 和实例 ID 分别校验唯一性；保留记录的布局可相互重叠，不占用画布。
- `WorkspaceExport`：格式标识 `all-in-one-workspace`、版本、导出时间、账号名称和完整工作区。

组件的业务对象放入 `config` 和 `data`，必须是 JSON 值。账号 ID 是文件定位边界；实例 ID 是账号内部的状态边界。布局使用 12 列，每行 32 像素，间距 16 像素，不允许重叠。缩小窗口只改变列的像素宽度，不重写持久化坐标。

新增实例按空闲位置放入画布。重新整理按默认尺寸逐行排列，保留实例 ID 与内容。

“仅移除卡片”把该实例从 `widgets` 移至独立的 `savedWidgets` 记录，不在组件内实现额外保存协议。同类型多个实例互不覆盖。恢复时先执行组件校验/迁移，按保存尺寸（至少当前组件最小尺寸）寻找空闲位置，再生成新实例 UUID；成功后移除对应记录，失败保留原记录。新 UUID 和 SDK 卸载保护共同阻止旧实例异步回调污染恢复后的卡片。缺失类型仍可恢复为占位卡。

“删除卡片及其设置和数据”只删除选中的在用实例；删除一份保留记录也只影响该记录。记录与账号一起导入/导出，账号删除时一起清理。飞书连接、令牌和缓存仍由账号级服务管理，不进入记录。

## 保存与切换

```text
组件修改 / 拖动结束
  → controller 创建经过校验的新状态
  → 350ms 合并变更 / 主动 flush
  → preload.save(workspace)
  → 主进程校验账号存在及文档归属
  → 全局写入队列
  → 普通修改保存上一份有效数据到 .bak；移除/恢复/删除记录时将新状态同步到 .bak
  → 写临时文件、fsync、rename
  → 界面显示已保存
```

controller 维护本地变更与已保存版本。写入期间发生新修改，会继续保存最新版本；单次失败不会破坏队列，内存里的未保存状态保留。切换账号、创建账号、导入导出前均先 flush，失败时不执行后续操作。关闭窗口通过主进程请求界面 flush，成功后再销毁窗口。

账号切换期间禁用编辑。组件以账号及实例 ID 为 key 重建，卸载时中止 `AbortSignal`。SDK 更新接口绑定原账号与原实例，并拒绝已卸载组件的更新，避免异步回调跨账号写入。

新增账号先写数据，再提交索引；索引提交失败时清理本次创建的数据。删除账号先验证替代账号可读，清理飞书凭证和请求（失败则中止删除），提交新索引并同步其备份，再清理工作区数据文件。工作区文件清理失败会显示提示，不把已经提交的删除伪装成未发生。

## 恢复与版本

读取校验同时检查文件格式、账号归属、实例唯一性和布局。主文件损坏时读取并验证备份，保留异常主文件副本，再恢复。两份均无效时停止，不创建空文件。缺失索引而目录已有账号文件时同样停止，以免遗失账号关系。

工作区及导出封装当前为 v2，新增必填 `savedWidgets` 数组。v0/v1 升级时补为空数组；v0 缺省的组件版本补为 1。账号索引与飞书凭证仍为 v1，分别执行版本校验。旧应用遇到 v2 会明确拒绝，不会静默丢弃保留记录。遇到更高版本拒绝读取/导入，保留现有文件。

主进程检查保存前后是否减少在用实例或保留记录；发生这些变化时将本次新状态同时用作恢复备份。成功删除后主文件及 `.bak` 均不含被删除记录，恢复也不会重新生成已消费记录。写入失败沿用控制器错误状态与重试，关闭/切换仍被阻止。以前导出的文件和 `.corrupt-*` 异常副本不在本次清理范围内。

组件版本独立于文档版本。已知组件通过 `migrate` 转换后再校验，成功结果自动保存；迁移失败或组件版本过新时显示卡片内错误并保留原始数据。未知组件保持原始配置、数据和版本，展示占位卡。

## 增加系统能力

如未来组件需要本地文件或系统能力，在 `DesktopAPI` 增加具体方法，再实现带参数校验的主进程处理器。不要开放任意路径读写或通用命令执行。涉及设备路径或密钥的组件，应单独定义本机绑定与迁移策略，当前 SDK 不提供秘密存储。

可复用的远程读取按「有效内存 → 允许落盘的有效磁盘缓存 → 网络」查找，所有分页方向和自动补页共用这条路径。主动刷新与实时数据的新鲜度检查可向来源重新验证，由主进程合并同键请求并遵守限流。缓存独立于工作区和导出，按账号或权限范围隔离。飞书日程只缓存于内存，凭证走独立加密存储。授权和远程写入按服务端确认结果。

## 飞书账号连接

`DesktopAPI.feishu` 暴露指定的连接查询、配置保存、授权/取消/断开、读取/刷新日程和按账号过滤的变更订阅。渲染进程只能提交配置；不返回 Secret 或令牌，也不能指定请求主机。CSP 继续禁止渲染进程直接调用远程 API。

`LoopbackOAuth` 仅在授权期间监听 `127.0.0.1:43821`，校验 state、Host、路径和单次使用，PKCE 校验码留在主进程。会话绑定发起的账号 UUID；账号切换不修改目标。五分钟超时、取消或删除会中止会话。取得身份、主日历与日程权限后才提交新连接。

`OneClickAuth` 为新账号提供默认入口：主进程调用飞书的个人应用注册协议，打开官方确认页并轮询取得该用户创建的应用凭证，然后进入设备授权，按指定 scopes 获取用户令牌。不调用本机 CLI、不嵌入共享 App Secret、不需要后端服务器；设备码仅在主进程内存保存。浏览器只能打开允许的 HTTPS 飞书域名，轮询处理 pending、slow_down、过期、取消与暂时网络失败，每个阶段受接口有效期限制（最长十分钟）。这里只支持飞书国内版，不静默切换到 Lark。

新应用凭证单独保存为 `authMode: 'device'`，之后授权复用应用；旧凭证没有此可选字段，继续走 PKCE 回调路径。工作区数据版本保持不变。取消用户授权保留已创建的应用凭证；解绑和删除清除本机凭证，但不删除飞书服务端应用。取消、删除、跨账号或迟到结果共用原有版本检查和事务提交逻辑。返回渲染进程的进度只包含阶段、用户确认码和有效期，不含设备码、Secret 或令牌。

`EncryptedVault` 使用 Electron 异步 `safeStorage`，在独立目录按 UUID 原子保存密文。配置草稿与当前授权使用的应用配置分开保存，更改 App ID 不破坏原连接。刷新令牌单次轮换，不建立凭证备份。读写与删除按账号排队，迟到的解密或写入不会复活被断开的连接。

`FeishuService` 按账号维护连接版本、AbortController、请求合并、刷新令牌单飞与内存缓存。解绑、重新绑定时递增版本并中止旧请求；返回结果检查版本，渲染端再校验账号与请求次序。网络失败暂存旧日程；授权或权限失败清空显示。日历实例的持久化数据为 `null`，工作区文件版本为 2，导入不迁移连接。

## 财联社 7×24

`DesktopAPI.telegraph` 暴露读取共享快讯、按校验后的秒级时间游标读取历史、订阅变化和按数字文章 ID 打开财联社详情页。渲染进程不能提交请求主机或任意外链，CSP 继续禁止直接访问远程 API。

`TelegraphClient` 在主进程中请求财联社网页接口。最新流共享 30 秒新鲜度和最多 50 条内存数据，缓存未命中的历史按秒级游标请求，每页最多 50 条。历史游标来自过滤前的上游时间戳，短页或过滤后空页仍能继续。最新与历史各只有一个进行中的上游请求，同一历史游标的并发请求合并，来自财联社的限流影响两条读取路径。返回空页结束本轮历史浏览，接口错误保留当前页面和重试游标。

卡片双向滑动时用可见条目锚定滚动位置。窗口按筛选后条目数控制内存，按实际视口高度判断自动补页。浏览期间以时间游标记录走过的页面。历史页优先从共享的 4 页短期内存缓存读取，其次从可重建的 `cache/cls-telegraph-v1` 读取，缺页按原游标请求上游。短期内存页闲置 5 分钟后释放。磁盘最多 16 MiB、128 页，按最近读写时间回收，24 小时未读写过期。启动和运行期间会清理过期文件。共享最新数据闲置 15 分钟后释放，卡片离开视口或应用隐藏 15 分钟后也会释放浏览窗口和游标。工作区只持久化组件元数据、布局和视图配置，组件业务数据为 `null`。

## 应用更新

`electron/updates/` 独立负责更新状态、GitHub 请求、缓存、Ed25519 清单校验、安全 ZIP 检查和安装协调；`DesktopAPI.updates` 仅提供受控操作和状态订阅，渲染层不能指定下载 URL 或安装路径。源码公钥同时编译到主进程和 `native/UpdateInstaller.swift`。更新相关状态不属于账号或工作区数据格式。

原生助手复制到独立事务目录后运行，不依赖即将替换的 Electron。采用同卷暂存、`RENAME_SWAP`、系统启动服务，以及读取账号数据前的双向启动确认。辅助程序只在用户点击重启安装后获得替换许可；正常退出不会触发安装。测试专用的临时目录支持仅存在于用 `UPDATE_TESTING` 编译的助手，发行构建不启用此编译条件。

发布流程、信任密钥、缓存策略及恢复边界见[自动更新与发布](updates.md)。
