# 邮箱管理与限制

飞书（IMAP / OAuth）、163、Gmail 共用同一套应用内账号隔离、缓存、列表归并、刷新和已读同步规则。新增来源只需要适配认证和服务商协议，不能另设一套缓存保留策略。参数统一维护在 [mail-policy.ts](../src/shared/mail-policy.ts)，主进程、前端和服务商适配器共同引用。

## 读取与同步

- 账号凭证按工作区独立加密保存，同一工作区的卡片和内嵌邮箱页共用邮件服务。断开账号时清除对应凭证和缓存；删除工作区时清除整个工作区的数据；切换工作区时取消旧请求并释放旧内存。
- 列表优先使用可用内存，其次使用加密磁盘历史摘要，缺失或需要更新时联网。所有来源均可保存历史摘要，飞书不再例外。刷新期间保留可读列表，连接错误在列表上方显示。
- 自动检查间隔为 60 秒，可见且前台时轮询，重新聚焦、可见或唤醒时检查新鲜度。成功获取的最新结果在 60 秒内复用；手动刷新使用 5 秒去重窗口。相同请求合并，同一 IMAP 账号的操作串行执行。服务商限流与重试等待仍遵循服务器响应。
- 最新时间段要向服务器校验，不作为长期历史块落盘。重启后可以先显示仍有效的磁盘历史摘要，同时读取最新邮件；从未加载过、未成功落盘或已淘汰的邮件仍需联网。此机制不保证重启后整个收件箱离线可用。
- 正文只在打开时读取，以纯文本显示并缓存在内存。打开未读正文后向服务器写入已读，成功后才同步卡片、邮箱页和磁盘摘要。授权和写操作不会用缓存代替服务器确认。

## 时间与容量的含义

| 对象 | 当前限制 | 范围和计数方式 |
| --- | --- | --- |
| 列表分页 | 每次最多 50 封 | 返回给界面的一页；不是总邮件数量上限 |
| 主进程摘要内存 | 1 个最新块 + 4 个历史块 | 每个工作区内的每个邮箱账号、每个收件／发件文件夹分别计算，按最近使用情况淘汰 |
| 正文内存 | 最多 8 封 | 当前工作区所有邮箱共享，先淘汰最久未访问的正文 |
| 内存闲置 | 10 分钟 | 最新列表、摘要块、正文及服务商内容缓存统一按上次访问计时；隐藏的列表也在 10 分钟后释放 |
| 磁盘块数 | 最多 128 个 | 当前应用数据目录下的全部工作区、账号和邮箱来源共同使用 |
| 磁盘总量 | 最多 16 MiB | 实际加密缓存文件的大小之和，含密文封装；不包含凭证或工作区布局 |
| 磁盘单块 | 不超过 1 MiB | 超大块不落盘，仍可使用内存和网络读取 |
| 磁盘闲置 | 48 小时 | 从最近写入或读取计时，读取会续期；后台已读同步不会让未访问的旧块永久保留 |

“缓存块”按 **工作区 + 邮箱账号 + 文件夹 + 时间范围** 标识，不是界面上的一页。同一时间段可能为空，也可能有多于 50 封邮件；密集时段会缩小范围。因此不能把 128 块换算为固定的 6,400 封邮件。

磁盘块数、字节数和闲置期限同时生效：写入后从最近使用的块开始保留，超限或过期的块会被清理。缓存使用时检查有效期，后台每分钟维护一次，因此失效不代表文件恰好在那一毫秒被物理删除。内容更新时间单独记录，读取旧块续期不会把旧邮件状态当成较新的数据。

内存的 10 分钟和磁盘的 48 小时都指**闲置保留时间**，不是“只显示最近 10 分钟／48 小时收到的邮件”。容量限制只影响本地复用，不删除服务器邮件、不限制向前翻阅历史。缓存淘汰后可以再次下载。内存按记录数和闲置时间限制，没有固定的整个进程 RAM 字节上限；网络也没有固定的每日流量上限。

## 验证

`tests/mail-service.test.ts` 覆盖四种连接方式重启后的磁盘读取、已读同步及隔离、一分钟新鲜度、手动刷新去重、十分钟内存闲置、四十八小时磁盘闲置和容量淘汰。`tests/desktop/mail.spec.ts` 在实际 Electron App 内验证列表、筛选、缓存展示和刷新交互。新增邮箱适配器时应纳入同一套管理行为测试。
